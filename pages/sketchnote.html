how this lab is organized

a one-page tour of where to put things. read it once; forget it; the structure will remind you.

pages/

One .html file = one route. Inline <style>, inline <script>. Ships as-is, no build step.

good for: essays · invites · landing snippets · this page

apps/<slug>/ — static

Vite + React + Tailwind. Lives at /apps/<slug>/. The build script bundles it into the root Worker's assets.

good for: timers · calculators · small interactive things

apps/<slug>/ — fullstack

Adds a per-app Cloudflare Worker, its own D1 database, and Better Auth wired in. Login, save-to-account, the works.

good for: journals · trackers · personal saas-y things

The thing that makes this layout work is its flatness. Every page is one level deep. Every app is one level deep. The build script auto-discovers what's there — no central registry, no manifest you have to remember to update. Add a folder; it appears. Delete it; it disappears.

The lab landing (the page you came from at /) is the only navigation. It's generated from whatever's in pages/ and apps/, so it stays in sync without you maintaining it.

no central manifest = nothing to forget to update

shortcuts to remember

  • pnpm scaffold page foo — add an HTML page
  • pnpm scaffold app foo — add a static app
  • pnpm scaffold app foo --fullstack --deploy — full lifecycle
  • pnpm scaffold rm foo — undo any of the above
  • pnpm deploy:all — push everything live
p.s. this page is itself one of the starter examples. when it's done its job, pnpm scaffold rm sketchnote and it's gone — won't haunt your landing.
